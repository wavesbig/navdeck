# 日期小组件展示规范

## 文档目的

本文梳理 NavDeck 中 `倒数日` 与 `正数日` 两类日期小组件在 `S / M / L` 三种尺寸下的展示逻辑、尺寸边界、状态切换和极端场景降级策略，用于统一后续设计、实现与验收标准。

本文基于当前实现整理，涉及的核心文件：

- `src/components/layout/WidgetBar.tsx`
- `src/components/widgets/DateWidgetDisplay.tsx`
- `src/components/widgets/CountdownWidget.tsx`
- `src/components/widgets/CountupWidget.tsx`
- `src/app/globals.css`

## 1. 当前实现基线

### 1.1 数据模型

- 一个日期卡片实例只允许绑定一个日期项。
- `倒数日` 与 `正数日` 都通过 `useDateItems(instanceId)` 读取实例级日期数据。
- 服务端 `POST /api/widgets/instances/:id/items` 已限制同一实例只能创建一条日期数据。
- 配置入口统一为卡片右键菜单的 `设置`，打开后使用 `Dialog` 编辑当前唯一日期。

### 1.2 共享展示骨架

两类日期卡片共用 `DateWidgetDisplay` 作为展示骨架，输入统一的视觉字段：

| 字段 | 含义 |
|---|---|
| `badgeLabel` | 状态标签，如 `未开始` / `临近` / `今天` |
| `dateLabel` | 日期摘要，如 `开始于 2026-08-25` / `下一次 8月18日` |
| `helperLabel` | 辅助解释，如 `14 天后开始累计` |
| `unitLabel` | 数字单位，如 `天` / `天后` / `今天` |
| `valueLabel` | 主数字显示值 |
| `tone` | 视觉语义色，当前为 `accent / success / secondary` |

### 1.3 单日期模式的现实影响

虽然 `DateWidgetDisplay` 仍保留了“主卡 + 列表行”的扩展能力，但当前 `CountdownWidget` 和 `CountupWidget` 都将 `maxItems` 固定为 `1`，因此：

- `S / M / L` 三档尺寸当前都只展示一个主日期；
- 列表行区域在当前业务规则下不参与实际渲染；
- `M / L` 与 `S` 的差异主要体现在：卡片宽高、主数字字号、文本留白和辅助文案是否展示完整。

这意味着日期小组件现在不是“多条列表卡”，而是“单日期信息面板”。

## 2. 三种尺寸卡片的视觉规格

### 2.1 网格尺寸规则

`WidgetBar` 采用两列网格：

- 列数：`2`
- 行高：`40px`
- 间距：`8px x 8px`

尺寸映射如下：

| 尺寸 | RGL 宽高 | 高度公式 | 默认栏宽 `360px` 下的外框尺寸 |
|---|---:|---|---|
| `S` | `1 x 2` | `2 * 40 + 1 * 8` | 约 `176 x 88` |
| `M` | `1 x 4` | `4 * 40 + 3 * 8` | 约 `176 x 184` |
| `L` | `2 x 4` | `4 * 40 + 3 * 8` | 约 `360 x 184` |

宽度公式：

```text
单列宽度 = (widgetBarWidth - 8) / 2
S / M 外框宽度 = 单列宽度
L 外框宽度 = 单列宽度 * 2 + 8
```

常见栏宽下的外框宽度参考：

| `widgetBarWidth` | 单列宽度 | `S / M` | `L` |
|---:|---:|---:|---:|
| 280 | 136 | 136 | 280 |
| 320 | 156 | 156 | 320 |
| 360 | 176 | 176 | 360 |
| 400 | 196 | 196 | 400 |
| 440 | 216 | 216 | 440 |
| 480 | 236 | 236 | 480 |

### 2.2 内容安全区

当前安全区由三层共同决定：

1. 卡片外框：`Card padding={2}` 用于 `S`，`Card padding={4}` 用于 `M / L`
2. 内层面板：`.date-widget-panel`
3. 主内容块：`.date-widget-reference`

因此，推荐把“可安全使用空间”理解为：

```text
外框尺寸
- Card padding
- date-widget-panel padding
- date-widget-reference padding
= 内容安全区
```

对于日期卡，最重要的是：

- `S` 必须把所有文字限制在 `3` 个层级以内；
- `M / L` 可以扩展到 `5` 个层级，但不得新增额外信息块。

### 2.3 布局区域划分

#### `S` 尺寸

只允许三段式布局：

```text
+----------------------+
| 顶部标识             |
| 主数字 + 单位        |
| 单行摘要             |
+----------------------+
```

具体规则：

- 顶部标识：只显示组件类型，如 `倒数日` / `正数日`
- 主数字区：主数字为第一视觉焦点
- 摘要区：将 `名称 + 日期摘要` 合并为一行，禁止再显示 footer

#### `M` 尺寸

允许四到五段式布局：

```text
+----------------------+
| 顶部标识 + 状态      |
| 主数字 + 单位        |
| 日期摘要             |
| 名称                 |
| 辅助解释             |
+----------------------+
```

#### `L` 尺寸

结构与 `M` 保持一致，但横向空间更大：

```text
+--------------------------------------+
| 顶部标识 + 状态                      |
| 主数字 + 单位                        |
| 日期摘要                             |
| 名称                                 |
| 辅助解释                             |
+--------------------------------------+
```

`L` 与 `M` 的差异不是“多模块”，而是“更宽松的可读性”。

### 2.4 当前字号与排版参数

#### 主数字字号

| 尺寸 | 主数字 class |
|---|---|
| `S` | `text-3xl` |
| `M` | `text-4xl` |
| `L` | `text-5xl` |

#### 通用文案参数

| 元素 | 当前参数 | 说明 |
|---|---|---|
| 顶部标识 | `0.68rem`，compact 时 `0.62rem` | 全大写、较大字距 |
| 日期摘要 | `0.9rem`，compact 时 `0.8rem` | 单行省略 |
| 辅助解释 | `0.68rem`，两行截断 | 仅 `M / L` 展示 |
| 标题 | 两行截断 | `S` 不再独立显示第二行标题 |

## 3. 正数日与倒数日的适用场景与状态规则

## 3.1 倒数日

### 适用场景

适合表达“目标日在未来或刚刚过去”的事件：

- 截止日
- 纪念日
- 生日
- 预约 / 行程
- 支持每年循环的重复目标日

### 触发条件与状态切换

| 条件 | 状态标签 | 主单位 | tone | 展示语义 |
|---|---|---|---|---|
| `recurring = true` 且 `days = 0` | `今天` | `今天` | `success` | 今天正好发生 |
| `recurring = true` 且 `days > 0` | `每年循环` | `天后` | `accent` | 下一次循环事件待到达 |
| 非循环且 `days = 0` | `今天` | `今天` | `success` | 今天就是目标日 |
| 非循环且 `days > 0` 且 `days <= 3` | `临近` | `天后` | `accent` | 临近截止 / 临近发生 |
| 非循环且 `days > 3` | `未到` | `天后` | `secondary` | 正常未来目标日 |
| 非循环且 `days < 0` | `已过` | `天前` | `secondary` | 目标日已过去 |

### 展示优先级

若未来允许恢复多日期展示，当前排序规则为：

1. `days >= 0` 的日期优先于 `days < 0`
2. 同分组内按 `abs(days)` 升序
3. 即：
   - 最近要到来的日期优先
   - 已过期日期按“离今天最近”优先

## 3.2 正数日

### 适用场景

适合表达“从某个起点开始累积”的事件：

- 在一起 / 纪念日累计
- 项目持续时间
- 打卡持续天数
- 自某日以来的运行 / 习惯 / 成就天数

### 触发条件与状态切换

| 条件 | 状态标签 | 主单位 | tone | 展示语义 |
|---|---|---|---|---|
| `days < 0` | `未开始` | `天后开始` | `accent` | 起点还未到 |
| `days = 0` | `今天开始` | `今天` | `success` | 今天是第 0 天 |
| `days > 0` | `进行中` | `天` | `success` | 已开始并持续累计 |

### 展示优先级

若未来允许恢复多日期展示，当前排序规则为：

1. `days >= 0` 的已开始项目优先于 `days < 0` 的未开始项目
2. 已开始项目按 `days` 降序排列
3. 未开始项目按 `abs(days)` 升序排列

即：

- 先展示“持续最久的当前项目”
- 再展示“最近即将开始的项目”

## 4. 统一展示规范

### 4.1 颜色体系

#### 语义色

| 语义 | 用途 | 当前实现 |
|---|---|---|
| `accent` | 临近、未开始、循环提醒等强提醒态 | 主数字红色 `#d71921` |
| `success` | 今天、进行中、正在累计 | 当前也沿用红色主数字，但语义上属于“积极进行态” |
| `secondary` | 正常未来态、已过态、弱提示 | 主数字弱化为前景色的低对比版本 |

#### 底板

| 主题 | 背景 | 前景 |
|---|---|---|
| Light | 白到浅灰的纵向渐变 | `#1b1b1d` |
| Dark | 深灰到黑的纵向渐变 | `#ffffff` |

### 4.2 字体使用标准

| 层级 | 字体 | 使用规则 |
|---|---|---|
| 主数字 | `KWGTDot47` 优先 | 仅用于数字主值 |
| 标题 / 重点文案 | `NType82Headline` | 名称、关键信息 |
| 辅助文案 | `NType82Regular` | 日期说明、辅助说明 |

规则：

- 一个卡片里只能有一个“主数字焦点”
- `S` 尺寸禁止同时出现两个同级重点文本
- 单位必须弱于主数字至少一个层级

### 4.3 标签与文案排版

| 元素 | 规范 |
|---|---|
| 顶部标签 | 单行、省略、字距放大、用于类型或类型 + 状态 |
| 日期摘要 | 单行、省略，不承担解释责任 |
| 名称 | `S` 合并进摘要，`M / L` 可独立成行 |
| 辅助解释 | 仅 `M / L` 显示，最多两行 |

### 4.4 图标与装饰元素

当前标准：

- 卡片正文不使用业务图标
- 不使用额外角标 / 徽章 / 大面积装饰纹理
- 交互装饰仅保留底板 hover 提升与轻阴影变化
- 旧的列表行装饰横线 `rail` 仅在多条列表模式下使用；在当前单日期模式中不应成为主视觉元素

## 6. 极端场景与降级策略

### 6.1 超长名称

#### 当前策略

- `S`：并入摘要行，单行省略
- `M / L`：名称行最多两行，超出截断

#### 推荐规则

- 超过 `12` 个中文字符时，优先保留名称前半段
- 不允许因为长名称挤压主数字区

### 6.2 超长日期文本

典型情况：

- `开始于 2026-08-25 08:30:00`
- `循环日期 · 原始设定 2026-08-18`

#### 当前策略

- 日期摘要单行省略
- `S` 尺寸将日期和名称合并后单行省略

#### 推荐规则

- `S` 只允许保留短日期格式，如 `8月18日` / `2026-08-31`
- `M / L` 优先显示短日期，不显示无必要的时间部分

### 6.3 多日期叠加

当前业务上已禁止同卡多日期，但仍需处理旧数据：

- 卡片展示层：仅按当前排序规则展示第一条
- 配置层：显示“检测到旧版多条数据，请清理多余日期”
- 旧数据只允许删除，不应再鼓励多条编辑

### 6.4 数字过长

典型情况：

- 正数日累计达到 `1000+`
- 倒数日长期历史数据出现大跨度数值

降级规则：

- 数字永远保持单行
- 如果数值位数超过 `4` 位，优先缩小数字字号，不压缩单位和摘要
- 不允许数字换行

### 6.5 高度不足

当 `S` 卡片高度不足时，优先级必须固定：

1. 顶部类型
2. 主数字 + 单位
3. 一行摘要

优先删除顺序：

1. footer
2. 独立名称行
3. 状态标签合并信息

即便信息被压缩，也必须保留“这是什么卡”和“数字是什么意思”。

## 7. 参数对照表

### 7.1 尺寸与信息层级

| 尺寸 | 外框尺寸（默认栏宽 360） | 信息层级上限 | 建议内容密度 |
|---|---|---:|---|
| `S` | `176 x 88` | 3 层 | 极简、单摘要 |
| `M` | `176 x 184` | 5 层 | 标准信息卡 |
| `L` | `360 x 184` | 5 层 | 宽松阅读卡 |

### 7.2 展示优先级

| 类型 | 第一优先级 | 第二优先级 | 第三优先级 |
|---|---|---|---|
| 倒数日 | 最近将到来 / 今天 | 临近事件 | 已过事件 |
| 正数日 | 已开始且累计最长 | 今天开始 | 即将开始 |

### 7.3 当前交互规则

| 交互 | 规则 |
|---|---|
| 打开设置 | 右键卡片，点击 `设置` |
| 编辑日期 | 在 `Dialog` 中编辑当前唯一日期 |
| 删除日期 | 在 `Dialog` 中点击 `删除`，二次确认 |
| Hover | 卡片轻微上浮，阴影增强 |
| Active | 卡片回到原位 |

## 8. 统一性结论

为保证不同尺寸下体验一致，后续日期卡片应遵循以下硬规则：

1. 所有尺寸都坚持“一个卡片只表达一个日期主题”
2. `S` 尺寸以“读懂数字”为目标，禁止塞入第二重点信息
3. `M / L` 维持相同的信息结构，只调整可读性和留白
4. 倒数日与正数日的差异只体现在状态语义、单位文案和优先级排序，不体现在版式骨架
5. 任意极端场景下，优先保护主数字、类型标识和单行摘要

## 9. 后续建议

基于当前截图和实现，最值得继续收敛的点有两个：

1. 为 `S` 尺寸建立独立的字体和留白 token，避免继续与 `M / L` 共用过多样式
2. 让 `success` 与 `accent` 在颜色上真正拉开，目前两者都偏红，语义区分还不够强
